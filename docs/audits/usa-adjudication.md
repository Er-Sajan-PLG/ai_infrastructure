# USA Audit Adjudication

**Scope:** adjudication of the Universal Software Auditor report for `ai_infrastructure` generated 2026-09-25 at commit `c0ce30da`. Findings are assessed against this repository's role as an AI infrastructure research and implementation laboratory, not as a deployed SaaS service.

Each item below records an explicit ruling. A deferred item is not a pass; it remains open until its stated trigger or review phase.

## Security

| Finding | Ruling | Evidence and rationale | Follow-up |
|---|---|---|---|
| Bandit B310 on `urllib.request.urlopen` in the new HTTP transport | **ACCEPTED — fixed** | Both call sites in `integrations/llm_http_transport/transport.py` have a targeted `# nosec B310`. Immediately before either call, `_require_http_url()` permits only `http` and `https`; offline tests verify that `file:` and custom schemes are rejected. Ruff's S310 suppression is separate. `make ci` passed after this change. | No later than the current transport merge: retain the per-call scope and rerun `make ci` after changes to URL validation or these calls. |
| Prompt injection / untrusted content overriding instructions (AI-001) | **DEFERRED — SEAM phase** | This repository builds components, not one deployed agent policy. Relevant attack surfaces are MCP server responses, tool outputs consumed as observations, and externally sourced repository research reports. Current controls include MCP approval seams, dispatcher allowlists, and the study pipeline's refusal to execute studied code; these do not establish a complete prompt-injection defense for composed systems. | Before a composed system is treated as production-ready: define trust labels/handling across those surfaces, document the consuming model boundary, and add adversarial tests. |
| Least privilege for agents and tools (AI-003) | **DEFERRED — SEAM phase** | MCP has an approval policy and the ReAct integration uses an explicit dispatch allowlist, but no single repository-wide authorization policy governs every composition. | Reassess when composing a system with real external side effects; require explicit permissions and denial tests before use. |
| Per-tenant RAG access controls (AI-007) | **OUT OF SCOPE for current phase** | No multi-tenant RAG implementation or tenant store exists in this repository. This is not evidence of a deployed cross-tenant vulnerability. | Reassess if a tenant-aware retrieval capability is proposed. |
| Human approval for consequential actions (AI-010) | **DEFERRED — SEAM phase** | The MCP client already has a mandatory approval seam, but the repository has no uniform action-risk contract spanning all future integrations. | Reassess before introducing irreversible or externally visible actions. |
| Scripted `api_key="scripted-key"` strings flagged by secret scanning | **FALSE POSITIVE** | [`.gitleaks.toml`](../../.gitleaks.toml) documents that these are deterministic test sentinels, not credentials; the default gitleaks rules do not match the value. | Sensitive-data logging flag in the trace-recorder quickstart | **FALSE POSITIVE for secret disclosure; improve example output** | The flagged example prints whether a known sentinel appears in the serialized off-record data, not the sensitive value itself. | Adaptive password hashing (SEC-025) | **OUT OF SCOPE** | There is no authentication system, user account store, or password handling in this repository. | Reassess only if authentication is added, which requires separate human review. |

## Audit recommendations not accepted as universal requirements

Recommendations such as password hashing, Docker/Kubernetes, IaC, OpenAPI generation, login journeys, money-path E2E tests, and tenant-scoped RAG controls are not implemented because their triggering product surfaces do not exist. They are not evidence of missing controls in a non-existent service. Any future capability that introduces those surfaces must reopen the corresponding adjudication.
