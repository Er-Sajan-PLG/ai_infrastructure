## Phase 1 queue

Priority order per charter §24 (dependency + verifiability first). Sources: [`../TAXONOMY.md`](../TAXONOMY.md) §4.

1. `tool-registry` (tools) — no dependencies, consumed by almost everything.
2. `model-provider-abstraction` (models) — no dependencies, consumed by everything above.
3. `react-agent-loop` (agents) — depends on 1+2; first end-to-end composition.
4. `execution-trace-recorder` (observability) — enables honest evaluation of 3.
5. `vector-memory-store` (memory), then `basic-rag-pipeline` (retrieval) — depends on 2/5.
6. `mcp-client` (mcp) — COMPATIBILITY candidate; narrow stdio client.

For each: RESEARCHED → UNDERSTOOD → DECIDED (ADR) → DESIGNED → IMPLEMENTED → TESTED — one stage at a time, no skipping (charter §4).

## What's deliberately NOT in Phase 1

- The study pipeline itself (Phase 2 machinery).
- Distributed/durable execution, GPU/deployment infrastructure, fine-tuning.
- Any external-service dependency (vector DBs, hosted eval platforms) — out of scope.

- **Session 3 (license + formatter):** Licensed **Apache-2.0** (`LICENSE`, `NOTICE`) after escalating to the maintainer — ADR-0002 is now Accepted, and `code_reused: true` is unblocked (subject to `attribution_requirements` + a `NOTICE` update). Also reduced to one formatter (ruff lints, black formats; ADR-0003 amended).
- **Session 4 (testing enforcement):** Found and closed two real holes, prompted by the question *"doesn't testing belong to setting up the environment?"* — it does, and the setup was incomplete. (1) `validate_catalog.py` accepted an **empty** `tests/` directory in `--strict` mode (checked existence, not content). (2) `pyproject.toml` had `testpaths = ["tests"]`, so **pytest never collected `catalog/`** — a capability could ship tests that no gate ever ran while `make check` stayed green. Fixed: empty `tests/`/`examples/` are errors in all modes; `testpaths` includes `catalog/`; CI runs the contract in `--strict`; 6 regression tests added (34 → 40). ADR-0004.
- **Session 6 (Phase 1 begins — `tool-registry` research + decision):** Phase 1 capability work finally started; sessions 1-5 are now recorded as **Phase 0 — Foundation** (ADR-0005), because charter §30 defines Phase 1 as *seeded capabilities* and `catalog/` is empty. Added `docs/phases/` with an executable plan per phase (Phase 1 detailed enough to work from). Four reference projects surveyed with mechanisms verified against **primary source** (not docs): OpenAI function calling, LangChain/LangGraph, MCP, Semantic Kernel. **Key finding: none of the four ships a real tool registry** — OpenAI has none, LangChain's is a per-node dict, MCP's identity dies with the connection, SK's is a fail-open god object. Three of them independently converge on splitting tool failures by *model-actionability*. Decision **ADR-0006: IMPLEMENT** a standalone JSON-Schema-native registry, zero runtime dependencies, with 10 evidence-traceable requirements and an explicitly accepted subset limitation. Found and fixed a **third enforcement hole** while doing it: `repo_status.py` checked that `research_records` was non-empty but never that the file existed — the same class of bug as ADR-0004's empty-`tests/` hole. 5 regression tests added (40 → 45).
- **Session 7 (`tool-registry` → DESIGNED):** Wrote `specifications/tool-registry.md` — the design is now frozen enough to implement against. Key decisions: **D-1** `ToolId(namespace, name)` frozen dataclass (identity must outlive a connection; MCP's dies on restart, SK's parses a flattened name). **D-2** a documented JSON Schema subset with **unknown keywords rejected loudly, never ignored** — silent permissiveness in a validator converts an unchecked boundary into an apparently-checked one. **D-3** explicit `injected: frozenset[str]` + two schema views, closing LangChain's verified forging vector without annotation magic. **D-4** failure taxonomy by model-actionability (`NOT_FOUND` never reaches a model; `INVALID_ARGUMENTS` and `EXECUTION_FAILED` do). **D-5/D-6** dynamic registration and async deliberately **deferred, not half-designed**. The spec states what we do *not* protect against as prominently as what we do — a registry is **not** a sandbox. Taxonomy → `DESIGNED`. Gates verified to actually enforce the claim (removing the spec produces exit 1).
- **Session 8 (`tool-registry` → IMPLEMENTED → TESTED):** First capability implemented. `catalog/tools/tool_registry/` — schema-subset validator, registry with the injection boundary, typed failure taxonomy, plus README, PROVENANCE (inspired-by, `code_reused: false`) and a runnable example. **116 tests pass** (was 103; 58 in the entry itself), including adversarial cases: a 2000-deep schema must fail cleanly rather than exhaust the stack, and a forged injected argument must have zero effect. **Three real bugs were found by the tests, not by review:** (1) injected arguments were added to `properties` but not `required`, so a missing host value surfaced as an opaque `TypeError` instead of `INVALID_ARGUMENTS`; (2) `__cause__` cannot be assigned on a frozen dataclass, so the original exception was not being preserved as claimed; (3) a test asserting internal errors propagate was itself wrong. Taxonomy → `TESTED`.
- **A third enforcement gap found while wiring the entry:** `make check` could not see that **41 relative Markdown links were broken** — category READMEs pointed at `../docs/...` where `../../docs/...` was required, and they had survived several sessions with every gate green. Added `scripts/check_links.py` (13 tests) wired into the Makefile, pre-commit hook and CI. Docs are a primary deliverable here, so a dangling reference is a defect: the documentation *claimed* a target existed and nothing checked the claim — charter §4 in miniature.
- **Session 9 (`model-provider-abstraction` → RESEARCHED → UNDERSTOOD → DECIDED):** Capability 2 of 7, and the blocker for `react-agent-loop` and `basic-rag-pipeline`. Three parallel surveys against primary sources (provider OpenAPI specs, and raw source at pinned versions: litellm 1.102.0, langchain-core 1.6.3, llama-index-core 0.14.24, openai-python main). Four new registry entries. **Decision (ADR-0007): IMPLEMENT** an abstraction that owns *shape*, not the *socket* — transport injected, zero runtime dependencies preserved. Specification written; taxonomy → `DECIDED`. **The findings that forced it:** (1) the three providers barely agree on anything — system prompts have three mechanisms (Anthropic has *no* system role), stream termination differs (`data: [DONE]` vs `message_stop` vs nothing), and tool arguments are a JSON *string* from OpenAI but parsed objects elsewhere (verified against OpenAI's published spec); (2) streaming usage needs three access strategies and may be absent entirely — verified that OpenAI requires `stream_options.include_usage` and returns it on a chunk with an *empty* `choices` array; (3) owning transport is what makes an abstraction heavy — verified LiteLLM's base deps are 14 packages including `boto3`, rooted in `class RateLimitError(openai.RateLimitError)`; (4) interface burden predicts integration pain — LangChain needs one method, LlamaIndex demands eight, and LlamaIndex's async is a façade that blocks the event loop.
- **Two survey claims corrected on independent verification**, recorded in the research record rather than smoothed over: LiteLLM's provider detection is *not* a naive if/elif cascade (it is 894 lines of per-provider helpers plus `provider_list` table lookups — the criticism stands, the mechanism description was wrong), and provider SDKs are lazily imported even though the 14-package base list is confirmed by direct fetch.
- **Session 10 (`model-provider-abstraction` → IMPLEMENTED → TESTED):** The neutral types, the error taxonomy, the streaming layer, and three adapters (OpenAI, Anthropic, Gemini) in `catalog/models/model_provider/`. **195 tests pass** (was 120; 75 in the entry). Tests 116 → 195. Taxonomy → `TESTED`; `react-agent-loop` is unblocked.
- **One real bug found by the tests, not by review:** `collect_stream` appended the accumulator's own `AccumulatedToolCall` records into the response's block list, so `ChatResponse.tool_calls` came back **silently empty** — the neutral type filter dropped them. A caller would have seen a response with no tool calls and no error. Fixed by converting to `ToolCallBlock`. This is the second session in a row where the test suite caught a defect that read as correct.
- **Two type-design defects found by mypy strict:** `ProviderStream` defined only `__iter__`, so it was not actually an `Iterator` — the public `stream()` return type was a lie that mypy caught. And the adapters narrowed a block union with `hasattr`/`getattr` instead of `isinstance`, which mypy rejected and which would have silently mis-encoded a tool result.
