## Phase 1 queue

Priority order per charter §24 (dependency + verifiability first). Sources: [`../TAXONOMY.md`](../TAXONOMY.md) §4.

1. `tool-registry` (tools) — no dependencies, consumed by almost everything.
2. `model-provider-abstraction` (models) — no dependencies, consumed by everything above.
3. `react-agent-loop` (agents) — depends on 1+2; first end-to-end composition.
4. `execution-trace-recorder` (observability) — enables honest evaluation of 3.
5. `vector-memory-store` (memory), then `basic-rag-pipeline` (retrieval) — depends on 2/5.
6. `mcp-client` (mcp) — COMPATIBILITY candidate; narrow stdio client.

For each: RESEARCHED → UNDERSTOOD → DECIDED (ADR) → DESIGNED → IMPLEMENTED → TESTED — one stage at a time, no skipping (charter §4).

## What's deliberately NOT in Phase 1

- The study pipeline itself (Phase 2 machinery).
- Distributed/durable execution, GPU/deployment infrastructure, fine-tuning.
- Any external-service dependency (vector DBs, hosted eval platforms) — out of scope.

- **Session 14 (`execution-trace-recorder` → RESEARCHED):** Capability 4 of 7, chosen because the dependency graph forced it: `basic-rag-pipeline` declares `depends_on: [vector-memory-store, model-provider-abstraction]` and `vector-memory-store` is still `DISCOVERED`, so it stays blocked. Six sources studied against primary material — OTel GenAI semantic conventions, Langfuse, LangSmith, MLflow, AgentOps, OpenInference. Five new registry entries (18 total). Taxonomy → `RESEARCHED`.
- **The finding that shapes the design: the six disagree on the taxonomy axis itself.** OTel models a node as an operation **verb** (`execute_tool`, `invoke_agent`) and has *no* node-kind enum. The other five model a kind **noun** (`TOOL`, `AGENT`, `LLM`). They also disagree on closedness (OTel closed; MLflow deliberately open with the reason in source: *"Not using enum as we want to allow custom span type string"*) and on whether the trace root is itself a span. **"Compatible with all six" is not a coherent goal**, and saying so is more useful than pretending otherwise.
- **The strongest convergence: no surveyed system makes a tool call a distinct class.** All six use one record type plus a type/kind label, and OTel puts the tool *result* as an attribute on the same span rather than a second signal. Splitting a call from its result would be a divergence with no justification.
- **The real interop hazard is time units, not taxonomy.** MLflow stores span times in **nanoseconds** and trace duration in **milliseconds in the same object** — one implementation disagreeing with itself. LangSmith derives latency in seconds; OTel specifies seconds for its one derived field; Langfuse and AgentOps state **no unit at all**. Every system agrees on *what* to time and disagrees on *what to call the unit*. That goes in the spec as a hard rule, not a style note.
- **OTel's content-capture policy reversed, and the reversal is visible.** `gen_ai.prompt` / `gen_ai.completion` are `Deprecated` with *"Removed, no replacement at this time"*, replaced by `Opt-In` structured attributes and an `Opt-In` event. The deprecation **date is not determinable** from what was fetched and is recorded as UNKNOWN rather than guessed. Of six systems, only OTel states a default-off policy — and it is the only one with a privacy review. We adopt the *rule* without claiming conformance.
- **Cost: Phase 1 declines it.** Four of six model cost, but each either embeds a price table or asks the caller, and MLflow's own docstring concedes *"not supported for all LLM providers."* OTel models it not at all. Record usage; expose cost later.
- **A method finding worth keeping:** both OTel pages fetched from the *old* repository location returned **HTTP 200 with a "this page has moved" stub**. A survey trusting status codes would have concluded the conventions were where they used to be. Separately, MLflow's default branch is **`master`, not `main`**, so every `main`-rooted raw URL 404s — "the path moved" was my first inference and it was wrong. Both recorded in the research record §11.
- **Session 15 (audit follow-up — `AI-003` closed, the audit's only genuinely unmet security rule):** The 2026-09-16 audit found least privilege **MISSING**, not inapplicable: `grep` for `allowlist|permitted|deny` across the loop returned nothing, `RegistryDispatcher.schemas()` advertised **every** registered tool with no filter, and `run()` had no `tools=` parameter. An agent run against a fifty-tool registry was offered all fifty regardless of the task. `RegistryDispatcher(registry, allowed=frozenset({...}))` now exists; `allowed=None` preserves the previous behaviour. **The restriction is enforced in both directions, and the second half is the one that matters:** `schemas()` hides a tool from the model, but `self._by_name` still maps every registered name, so a model emitting a name it remembered from a system prompt or an earlier run would have been served — `dispatch()` refuses it. Refusal reports `kind="not_found"` with `model_visible=False`, identical to a name that does not exist, because telling a model *"that tool exists but you may not use it"* also tells it the tool exists. An unknown name in `allowed` raises `ValueError` at construction rather than being silently ignored: a typo in a policy should fail before a model call is paid for. **15 new tests** (317 total), and the `dispatch()` clause is **proven load-bearing rather than assumed** — removing it fails exactly the three tests that assert it, and restoring it passes all fifteen.
- **A second finding from the same pass: the audit tool and `gitleaks` disagree, and that is worth recording.** USA's `SEC-001` flagged two `api_key="scripted-key"` literals in `integrations/agent_loop_end_to_end/system.py` as CRITICAL hardcoded credentials. They are the literal handed to `ScriptedTransport`, which returns canned HTTP responses from a list and never opens a socket. `gitleaks` — the tool actually designed for this — scans the same tree and the full 23-commit history and reports **no leaks**. The audit tool cannot know the string is a sentinel because sentinel-ness is a property of the call graph, not of the text. Recorded as adjudicated-false-positive rather than silenced; moving the placeholder into an environment variable would satisfy the linter and imply the integration needs configuration it does not.
