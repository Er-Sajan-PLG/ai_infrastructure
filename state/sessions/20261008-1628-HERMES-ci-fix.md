## Problem

All 5 remote CI runs failed. Root cause: `.github/workflows/ci.yml` line 65 has
`enable-cache: true` on the `setup-uv` action, but the repository has no `uv.lock`
file. The repo uses `requirements-dev.txt` as its lock file (see pyproject.toml and
requirements-dev.txt header). `setup-uv` with `enable-cache: true` requires a
`uv.lock` to cache against; without it, the action errors out immediately:

```
No file in /home/runner/work/ai_infrastructure/ai_infrastructure matched to [**/uv.lock]
```

## Fix

Remove `enable-cache: true` from the setup-uv step. The repo's lock file is
`requirements-dev.txt`, not `uv.lock`. Caching is a nice-to-have; the pinned
toolchain in `requirements-dev.txt` is what guarantees reproducibility.
