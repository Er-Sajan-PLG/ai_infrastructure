## Problem

All 5 remote CI runs failed. Root cause: `.github/workflows/ci.yml` line 65 had
`enable-cache: true` on the `setup-uv` action, but the repository has no `uv.lock`
file. The repo uses `requirements-dev.txt` as its lock file. `setup-uv` with
`enable-cache: true` requires a `uv.lock` to cache against; without it, the action
errors out immediately.

## Fix 1: setup-uv cache (commit `2353698`)

Removed `enable-cache: true` from the setup-uv step. The pinned toolchain in
`requirements-dev.txt` is what guarantees reproducibility; caching is a
nice-to-have that cannot work without uv.lock.

## Fix 2: inventory.py unreadable directories (commit `9e1c13c`)

After Fix 1, CI ran the actual gates and found a second failure:
`test_unreadable_directory_does_not_abort_the_study` — `inventory.py` crashed
with `PermissionError` when encountering an unreadable directory (chmod 0o000).

Three functions had unguarded `is_file()`/`is_dir()`/`iterdir()` calls:
- `_count_nested_manifests` — the one that failed
- `_detect_packages` — same pattern, same risk
- `_detect_markers` — same pattern, same risk

Added `try/except OSError` guards mirroring the handling already present in
`_walk`. An unreadable directory is skipped, not fatal: a permissions quirk in
a third-party tree must not abort a study.
