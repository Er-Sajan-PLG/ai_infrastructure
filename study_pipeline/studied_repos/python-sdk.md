### STRONG (2)

*Two independent lines of evidence (multiple module-bearing directories, or a directory plus a declared dependency).*

#### Observability / tracing — `observability`

**Category:** `observability`

**Evidence** (directory or manifest evidence):

- `docs_src/logging/`
- `docs_src/opentelemetry/`

**Limitation:** A project that calls `logging.info` everywhere has the name without the abstraction. The distinction matters and is not visible here.

#### Protocol client (MCP / tool protocol) — `protocol-client`

**Category:** `protocols`

**Evidence** (directory or manifest evidence):

- `docs_src/client/`
- `docs_src/client_callbacks/`
- `docs_src/client_transports/`
- `docs_src/legacy_clients/`
- `docs_src/oauth_clients/`
- `docs_src/protocol_versions/`
- `src/mcp/`
- `src/mcp-types/`

**Limitation:** `client/` is overwhelmingly an HTTP client in most projects, not a protocol abstraction. Treat this category as the weakest signal.

### MODERATE (4)

*One line of evidence: a module-bearing directory, or a declared dependency by itself.*

#### Caching layer — `caching`

**Category:** `performance`

**Evidence** (directory or manifest evidence):

- `docs_src/caching/`

**Limitation:** A caching module is frequently small and inlined into a client rather than given its own directory, so absence means little. Deliberately does NOT match a bare `store`: `vector_stores/` and `graph_stores/` are data stores, not caches, and matching them reported LlamaIndex's storage layers as a caching layer.

#### Memory / state persistence — `memory`

**Category:** `memory`

**Evidence** (directory or manifest evidence):

- `docs_src/session_groups/`

**Limitation:** A `memory/` directory is frequently a stub in an early project. Check module size before treating it as implemented machinery.

#### Model provider abstraction — `model-provider`

**Category:** `models`

**Evidence** (directory or manifest evidence):

- `docs_src/completions/`

**Limitation:** Most projects have one provider module. The interesting question — whether more than one provider is actually supported — requires reading the modules, not the directory name.

#### Tool / function registry — `tool-registry`

**Category:** `tools`

**Evidence** (directory or manifest evidence):

- `.claude/skills/`
- `docs_src/tools/`
- `.claude/skills/test-quality/`
- `src/mcp/server/mcpserver/tools/`

**Limitation:** Cannot distinguish a decorator-based registry from a plain dict of callables, which are very different designs.
